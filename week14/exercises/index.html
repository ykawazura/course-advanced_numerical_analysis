    演習問題

    解答について

    各演習には模範解答を用意してあるが、パスワードで保護されている。授業中に配布されるパスワードを入力すると、その問題の解答が表示される。問題ごとにパスワードは異なる。

    演習1・2はOpenMP の基本のサンプルコードを、演習3は性能を測るのサンプルコードを、演習4は領域分割のサンプルコードを土台にすればよい。演習1で負荷分散（仕事の分け方）を、演習2でデータ競合の4つの対処の使い分けを、演習3で赤黒順序付けによる並列化を、演習4で切り方が通信量をどう変えるかを扱う。

    時間の測定値は環境で変わる

    以下の解答に載せた時間・速度向上は、Apple M2 Max（論理コア 12＝性能コア 8＋効率コア 4）での実測値である。皆さんの環境では数字が違って当然である。採点はグラフの形と説明で行う——「何倍出たか」ではなく、「どこで頭打ちになったか」「なぜそうなるのか」を書くこと。

    測定にあたっては、性能を測るページの作法——clock() ではなく omp_get_wtime() を使う、複数回測って最小値を採る、-O2 を付ける、答えが変わっていないことを毎回確認する——を守ること。

    演習1（基礎）

    数値積分 \(\displaystyle\pi=\int_0^1\frac{4}{1+x^2}\,dx\) を OpenMP で並列化し、スレッド数と実行時間の関係を測る。さらに、1回あたりの仕事量が揃っていないループで何が起きるかを調べる。

    (a) 中点則を #pragma omp parallel for reduction(+:s) で並列化し、\(n=2\times10^7\) で逐次版と答えを比べよ。差は出るか。出るならなぜか。

    (b) \(n=2\times10^8\) として、スレッド数 \(1,2,4,6,8,10,12\) での実行時間・速度向上・並列化効率を測れ。本文のヤコビ反復（性能を測る）と比べて、伸び方はどう違うか。違いの原因は何か。

    (c) 次のループは \(i\) が大きいほど1回の仕事が重い（三角形の負荷）。

    #pragma omp parallel for
for (int i = 0; i < n; i++) {
    double v = 0.0;
    for (int j = 0; j < i; j++) v += 1.0/(1.0 + j);
    b[i] = v;
}

    \(n=30000\)、12 スレッドで、schedule(static)（既定）・schedule(static,1)・schedule(dynamic,64)・schedule(guided) の4通りの実行時間を測り、差が出る理由を説明せよ。

    ヒント
    • (a) 並列化しても足す順序が変わるだけである。浮動小数点の加算は結合則を満たさないので、答えは一致しない。どの程度ずれるかを見て、それが問題になる大きさかを判断すること。
    • (b) スレッド数は omp_set_num_threads(nth) で変える。実行時間は短いので、3回測って最小値を採る。この計算機の論理コア数は omp_get_num_procs() でわかる。
    • (c) schedule を書き換えるたびにコンパイルし直すのは面倒である。#pragma omp parallel for schedule(runtime) と書いておくと、実行時に omp_set_schedule(omp_sched_dynamic, 64) のように関数で切り替えられる。
    • (c) 分け方を変えても答えが変わらないように書いておくこと。上のように結果を b[i] に入れて和は後から逐次で取れば、どの分け方でもビット単位で一致する。そうしておけば「速くなったが値が変わった」という心配なしに性能だけを比べられる。

    解答（🔒 パスワードを入力すると表示）

    演習2（基礎）

    \(n\) 個の値を \(N_b\) 個の階級に数え上げるヒストグラムを並列化する。素朴に

    #pragma omp parallel for
for (long i = 0; i < n; i++) h[v[i]]++;

    と書くと答えが合わない。原因を確かめ、4通りの対処を正しさと速さの両面で比べよ。

    (a) h[v[i]]++ がなぜ壊れるのかを、この文が機械語で何段の操作になるかから説明せよ。\(n=10^7\)、\(N_b=16\) で試し、合計が \(n\) に足りているかも確認せよ。

    (b) critical・atomic・スレッドごとの部分ヒストグラム・reduction(+:h[:16]) の4通りを実装し、それぞれ5回ずつ実行して正しさを確かめよ。

    (c) 4通りの実行時間を逐次版と比べよ。逐次より遅くなるものはどれか。なぜそうなるのか。

    (d) 部分ヒストグラムを long part[nth][16] のように詰めて確保すると、論理的には競合していないのに遅くなることがある。この現象の名前と原因、対処を述べよ。

    ヒント
    • (a) h[b]++ は「\(h[b]\) を読む → \(1\) を足す → 書き戻す」の3段である。2つのスレッドが同じ \(b\) に対してこれを同時に行うと、片方の更新が上書きされて消える。したがって合計は \(n\) より小さくなる。
    • (b) 入力データは毎回同じにしておくこと。rand() ではなく xorshift のような自作の擬似乱数を決まった種から回せば、何スレッドで走らせても同じ列が出る。
    • (c) critical は名前のない区間がすべて同じ鍵を共有することに注意。\(10^7\) 回の更新すべてが1本の門に並ぶ。atomic は門の手続きこそ軽いが、16 個しかない更新先を 12 スレッドが奪い合う。
    • (d) キャッシュの読み書きはバイト単位ではなくライン単位（多くの計算機で 64 バイト＝ long 8個分）である。別々の要素でも同じラインに載っていれば、片方を書くだけでもう片方のコアのキャッシュが無効になる。

    演習3（応用）

    第10回で「ガウス＝ザイデル法は素朴には並列化できない」と述べた。その理由と、赤黒順序付け（red-black ordering）による回避を確かめる。

    2次元ポアソン方程式

    \[ -\left(\partial_x^2 u+\partial_y^2 u\right)=2\pi^2\sin\pi x\,\sin\pi y \quad\text{on }(0,1)^2, \qquad u\big|_{\partial\Omega}=0 \]

    を対象とする（厳密解 \(u=\sin\pi x\sin\pi y\)）。格子点を市松模様に2色（赤・黒）に塗り分けると、同じ色の点どうしは互いを参照しない。そこで「赤をすべて更新 → 黒をすべて更新」という順序にすれば、各色の中は完全に並列化できる。

    (a) \(N=31,63,127\) について、ヤコビ法・ガウス＝ザイデル法（自然順序）・ガウス＝ザイデル法（赤黒順序）・SOR（赤黒順序、\(\omega=2/(1+\sin\pi h)\)）の反復回数を比べよ。赤黒に並べ替えると収束は遅くなるか。

    (b) \(N=127\) の赤黒 SOR について、スレッド数 \(1,2,4,8,12\) での反復回数と最終誤差を比べよ。次に、自然順序のまま #pragma omp parallel for を付けた版でも同じ表を作り、両者の違いを述べよ。

    (c) \(N=1023\)、反復回数を 200 に固定して、赤黒 SOR の速度向上を測れ。演習1の \(\pi\) の積分ほど伸びない理由を2つ挙げよ。

    ヒント
    • (a) 赤黒順序で色 \(c\) の点を回すには、行 \(i\) について for (j = 1 + ((i + c) & 1); j <= n; j += 2) とすればよい。\(i+j\) の偶奇で色が決まる。
    • (a) 5点差分の行列はプロパティ A（赤黒に分けられる性質）を持つ。この場合、赤黒順序でも自然順序でもガウス＝ザイデル法の収束率は同じ \(\cos^2\pi h\) になる、というのが理論の帰結である。実測でも確かめること。
    • (b) 自然順序のまま並列化すると、\(u_{i-1,j}\) が「更新済み」か「まだ」かがスレッドの進み具合で決まる。答えが毎回違うことを確かめよ。
    • (c) 1つはメモリ律速（性能を測るの議論）。もう1つは1点おきに飛ばして読むことによるキャッシュ効率の低下である。

    演習4（発展）

    2次元の領域分割において、同じ台数でも切り方によって通信量が変わることを確かめ、通信を含めた実行時間を見積もる。

    第12回の2次元拡散方程式を FTCS で解く。内部格子 \(N\times N\) を \(P_x\times P_y\) 個の長方形に分け、各区画に幅1の袖を付ける。袖の交換は配列のコピーで代用してよい（MPI は不要）。

    (a) \(N=256\)、\(P=16\) 台を \(1\times16\), \(2\times8\), \(4\times4\), \(8\times2\), \(16\times1\) と並べ、1ステップあたりの袖セル数・通信の回数・分割しない計算との最大差を比べよ。

    (b) \(P=4,16,64\) について、帯状分割（\(P\times1\)）と正方分割（\(\sqrt P\times\sqrt P\)）の袖セル数の比を求めよ。台数とともにどう変化するか。

    (c) 1点の更新に \(t_c=1\) ns、値1個の転送に \(t_w=8\) ns、通信1回の立ち上がりに \(t_\ell=2\ \mu\)s かかる計算機を仮定する。\(N=1024\)、\(P=1,4,\dots,4096\) について、正方分割と帯状分割の1ステップあたりの実行時間と速度向上を見積もれ。どこで逆転するか。上限はいくらか。

    (d) 3次元 \(N^3\) の格子を \(P\) 台に分ける場合、板状（1次元分割）・柱状（2次元分割）・立方（3次元分割）の通信/計算比を求め、\(N=256\)、\(P=8,64,512,4096\) で数値を比べよ。

    ヒント
    • (a) 5点ステンシルなので角の値は要らない。上下の隣とは \(b_y\) 個ずつ、左右の隣とは \(b_x\) 個ずつをやり取りする。
    • (a) 差が \(0\) になることを必ず確かめること。ならなければ袖の交換か添字を間違えている。
    • (b) 帯状分割の袖は \(2(P-1)N\)、正方分割は \(4N(\sqrt P-1)\) である（外周の境界には隣がいないので \(-1\) が付く）。
    • (c) 1台あたりの時間は「計算 \(+\) 通信」で、計算が \(N^2/P\cdot t_c\)、通信が「袖の個数 \(\times\,t_w\) ＋ 通信の回数 \(\times\,t_\ell\)」である。正方分割は隣が4つ、帯状分割は2つ。帯状分割は \(P>N\) では成立しない（1台が1行に満たない）。
    • (c) \(P\to\infty\) で計算は \(0\) に近づくが、通信の立ち上がり時間は残る。上限は \(N^2t_c/(4t_\ell)\) である。
    • (d) 板状は \(2N^2\)、柱状は \(4N^2/\sqrt P\)、立方は \(6N^2/P^{2/3}\)。計算量 \(N^3/P\) で割ること。
